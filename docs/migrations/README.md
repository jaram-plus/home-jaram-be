# 손으로 실행하는 마이그레이션

이 저장소는 스키마를 `ddl-auto: update` 로 관리하고 Flyway·Liquibase 가 없다.
Hibernate 가 메우지 못하는 것 — 데이터 이관, **이미 있는 제약 변경**, 인덱스,
`NOT NULL` 추가 — 은 여기에 SQL 로 남기고 사람이 실행한다.

## 규칙

- 파일 이름은 `YYYY-MM-DD-무엇을.sql`.
- 맨 위에 **왜 필요한지**와 **언제 실행해야 하는지**(배포 전/후)를 적는다.
- 멱등하게 쓴다. 두 번 실행해도 결과가 같아야 한다.
- 새 DB 는 Hibernate 가 처음부터 맞게 만드는 경우가 많다. 그럴 때는 "이미 떠 있던
  DB 에만 필요하다"를 파일에 적어 둔다.

## 알려진 한계

`ddl-auto: update` 는 **이미 있는 체크 제약을 고치지 않는다.** enum 에 값을
더하면(`MemberStatus` 등) 기존 DB 의 `<table>_<column>_check` 에는 그 값이 빠진
채로 남아, 새 값을 처음 쓰는 순간 실패한다. enum 을 늘릴 때마다 여기에 ALTER 를
남겨야 한다 — 이 반복이 부담이 되면 Flyway 도입을 검토할 시점이다.
